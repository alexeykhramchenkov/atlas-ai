# Как переносить изменения ATLAS

Единица переноса — версия в Git: код, тесты и изменения таблиц правил. Тестовые факты, токены и настройки подключения не копируются в рабочую базу.

1. Разработка ведётся в ветке `codex/<задача>` этого репозитория. Перед новой задачей брать актуальный рабочий main: в нём могут быть исправления, которых нет в старой тестовой папке.
2. В каждом релизе `releases/<id>/manifest.json` фиксирует исходную рабочую версию, контрольные суммы тестовых файлов, состав правил, проверки и состояние экспериментальных функций. `rules.json` хранит изменения правил по смысловому ключу, а не по ID строк тестовой базы.
3. Проверить разницу с предыдущим общим релизом, объединить обе стороны изменений, запустить тесты. Для аудита старой тестовой папки: `python scripts/release_audit.py --test-root /absolute/path/to/test --output /tmp/atlas-differences.json`. Разница сама по себе не означает, что тест новее.
4. Перед правилами сохранить закрытую копию затрагиваемых рабочих строк. Обновлять их одной транзакцией с проверкой, что они не изменились после подготовки. Сохранять рабочие ID. Без удаления фактов и без переноса тестовых данных.
5. Публиковать совместимый код, дождаться ACTIVE в Railway. Затем применить правила и проверить ответы в настоящем рабочем Telegram. Контракты и изменения поведения согласовываются в пределах задачи; выключенный эксперимент не включается при обычном копировании релиза.
6. После проверки присвоить Git-тег `atlas-prod-<id>`. Записать версию, результат и доказательства в журнал релизов. Секреты и резервные копии рабочих данных в Git не добавлять.

Откат: вернуть предыдущий Git-тег и сохранённые затронутые правила, предварительно проверив отсутствие более новых изменений. Одного отката кода недостаточно, если менялись таблицы правил.

Старая тестовая папка пока не является отдельным Git checkout. Не синхронизировать её поверх main автоматически. Новые задачи следует выполнять в ветках этого репозитория; до перехода на такой порядок использовать аудит и явный список файлов/правил релиза.
